# 🧰 ServerTools (Xray VPS Optimizer)

ابزار **بهینه‌سازی حرفه‌ای سرور لینوکس** با **مصرف زمان‌اجرای صفر (Zero-Footprint)** — طراحی‌شده برای زیرساخت‌های VPN پرترافیک: نودهای Xray/Reality (`marzban-node`، `pg-node`/Pasarguard، `marznode`)، پنل‌های Marzban/Pasarguard، وایرگارد، `x-ui` و Hiddify — و همچنین بهینه‌سازی عمومی هر سرور لینوکسی.

> نسخهٔ فعلی: **v2.16.0** · تک‌فایل بدون وابستگی خارجی · اجرا با دسترسی `root` · [آخرین نسخه در Releases](https://github.com/Saj-1992/Xray-VPS-Optimizer/releases/latest)  
> نسخهٔ ۱ در [`legacy/`](legacy/) فریز شده و دیگر به‌روزرسانی نمی‌شود.

📖 **[راهنمای جامع صفر تا صد و تفسیر کامل پروژه ← docs/GUIDE.md](docs/GUIDE.md)**

## 📥 نصب و اجرای سریع

اجرای مستقیم (بدون نصب):

```bash
bash <(curl -fsSL4 https://raw.githubusercontent.com/Saj-1992/Xray-VPS-Optimizer/main/dist/server-tools.sh)
```

نصب به‌عنوان دستور `st` در سیستم (پیشنهادی):

```bash
bash <(curl -fsSL4 https://raw.githubusercontent.com/Saj-1992/Xray-VPS-Optimizer/main/dist/server-tools.sh) --install
```

پس از نصب، کافی است در هر مسیر دستور `st` را اجرا کنید. برای به‌روزرسانی به آخرین نسخه:

```bash
st --update
```

> اگر `curl` ندارید از `wget -qO-` استفاده کنید، و اگر سرور فقط IPv6 دارد فلگ `-4` را از `curl` بردارید.

## 🚀 سریع‌ترین شروع (یک دستور، کل سرور بهینه)

```bash
st go                  # تشخیص خودکار، بهینه‌سازی کامل و نمایش نمرهٔ سلامت — بدون هیچ سؤالی
st go --users 10000    # تنظیم ظرفیت conntrack و هشدار RAM بر اساس تعداد کاربر همزمان
st boost               # اعمال دوبارهٔ اولویت CPU و محافظ OOM برای سرویس‌ها و کانتینرهای پروکسی
```

## 🧠 تفسیر کلی: ServerTools چگونه کار می‌کند؟

بسیاری از اسکریپت‌های بهینه‌ساز با نوشتن مقادیر ثابت و بدون بررسی وضعیت سیستم، باعث افت کارایی یا از دست رفتن دسترسی به سرور می‌شوند. **ServerTools** بر پایهٔ معماری لایه‌ای، ظرفیت‌محور و قابل بازگشت ساخته شده است:

1. **لایهٔ پایه (همیشه اعمال می‌شود):** فعال‌سازی **BBR** به همراه صف پیش‌فرض **`fq_codel`** (و امکان انتخاب `fq` یا `cake` با `--qdisc`)، تنظیم بافرها و صف‌های شبکه متناسب با RAM سرور، بهینه‌سازی تایمرها و keepalive، سخت‌سازی امن هسته، `tcp_min_snd_mss` (رفع CVE-2019-11479) و افزایش سقف فایل‌ها و mapها.
2. **لایهٔ تخصصی Workload (نودهای VPN):** تشخیص خودکار سرویس‌ها و کانتینرهای فعال روی سرور (`marzban-node`، `pg-node`، `xray`، `x-ui`، `hiddify`، `sing-box`، `hysteria`، `wireguard` و...)، فعال‌سازی فورواردینگ IPv4+IPv6، سایزدهی هوشمند جدول `conntrack` بر اساس RAM یا تعداد کاربر (`--users`) و رزرو خودکار پورت‌های در حال گوش‌دادن (`ip_local_reserved_ports`) تا کانکشن‌های خروجی پورت اینباندها را اشغال نکنند.
3. **لایهٔ دیتاپث و کارایی (Perf & Priority):** پخش پردازش کارت شبکه روی تمام هسته‌های CPU (`RPS/RFS/XPS`)، تنظیم governor روی `performance`، تنظیم `THP` روی `madvise` و دادن اولویت CPU/OOM به پروسه‌ها و کانتینرهای پروکسی — همگی بدون قطعی و بدون پردازش پس‌زمینه.
4. **بخش تکمیلی (Extras):** ساخت Swap (از نوع `zram` یا فایل، سازگار با Btrfs)، افزایش سقف `nofile` به یک میلیون (در PAM و systemd)، محدودسازی حجم لاگ `journald` + تنظیم NTP، و تنظیم DNS پایدار که پس از ریبوت نیز باقی می‌ماند.

همهٔ تغییرات **Idempotent** هستند؛ یعنی اجرای دوبارهٔ آن‌ها کاملاً امن است و سیستم را بدون ایجاد تنظیمات تکراری به همان وضعیت مطلوب می‌رساند.

## 🛡️ مسدودساز ISP های ایران (`st isp`)

از منوی **Security ← 5** یا به‌صورت مستقیم از خط فرمان می‌توانید رنج IP اپراتورهای ایرانی (همراه اول، ایرانسل، مخابرات، رایتل، شاتل، آسیاتک، پیشگامان، مبین‌نت و پارس‌آنلاین) را روی کل پورت‌ها یا پورت‌های دلخواه مسدود کنید:

- **ساخته‌شده روی `ipset`**: جست‌وجوی با سرعت ثابت حتی با هزاران رنج IP.
- **پوشش کامل Docker**: قوانین روی زنجیرهٔ `DOCKER-USER` هم اعمال می‌شوند تا پورت‌های کانتینرها باز نمانند.
- **ضد قفل‌شدن**: پورت SSH و IP فعلی شما همیشه به‌صورت خودکار معاف می‌شوند.
- **پشتیبانی از IPv6**: برای همراه اول و ایرانسل در صورت فعال بودن IPv6 سرور اعمال می‌شود.
- **آفلاین و داخلی**: دیتابیس رنج‌ها (`data/isp`) درون خود اسکریپت تعبیه شده و به اینترنت نیازی ندارد. (ایده و لیست‌های پایه از [Kiya6955/IR-ISP-Blocker](https://github.com/Kiya6955/IR-ISP-Blocker)).

```bash
st isp status                 # نمایش وضعیت فعلی و اپراتورهای مسدودشده
st isp block mci,mtn          # مسدود کردن همراه اول و ایرانسل
st isp unblock mtn            # باز کردن ایرانسل
st isp scope 443,8443         # محدود کردن بلاک به پورت‌های خاص (یا all)
st isp check 1.2.3.4          # بررسی تعلق IP به اپراتورها و وضعیت دراپ زنده
st isp live --watch           # مشاهدهٔ زندهٔ تعداد کانکشن‌های هر اپراتور به سرور
st isp update                 # دریافت آخرین لیست رنج‌ها از مخزن و اعمال مجدد
```

## 🧭 امکانات منوی تعاملی (`st`)

| بخش منو | امکانات کلیدی |
| --- | --- |
| **1. Optimize** | **Quick** (تشخیص خودکار + پرسش تعداد کاربر)، **One key** (`st go` بدون سؤال)، **Custom** (انتخاب دستی پروفایل، تیر و ماژول‌ها) |
| **2. Status & Health** | نمرهٔ سلامت ۰ تا ۱۰۰، نمایش ظرفیت باقی‌مانده (conntrack / RAM / CPU)، گزارش کامل سیستم و **Doctor** برای تشخیص تغییر یا پریدن تنظیمات (Drift) |
| **3. Security** | فایروال **UFW** (با محافظت خودکار SSH)، **fail2ban** (تنها سرویس اختیاری مقیم ~20MB)، سخت‌سازی **SSH** (اعتبارسنجی با `sshd -t`)، محدودسازی API نود و **Iran ISP Blocker** |
| **4. Tools** | ماتریس پینگ (ایران + جهان)، **اسپیدتست (Ookla یا HTTP با انتخاب سرور)**، بنچمارک، **Smart MTU/MSS**، **Conntrack NOTRACK**، **کنترل کامل IPv6**، نمای زنده، تغییر میرور APT، گزارش پشتیبانی (`--report`) و بخش **Node & Docker** |
| **5. Rollback** | بازگردانی آخرین اجرای ثبت‌شده (`--rollback`) یا بازگشت کامل به وضعیت پیش از اولین اجرای ServerTools (`--rollback-original`) |

## 📦 نصب رسمی پنل و نود (`st setup`)

با دستور `st setup` می‌توانید نود **Pasarguard (`pg-node`)** یا پنل **x-ui (`alireza0/x-ui`)** را مستقیماً با نصب‌کنندهٔ رسمی خودشان نصب کنید. پیش از اجرا، اسکریپت بررسی نحوی (`bash -n`) شده و آدرس منبع به همراه `sha256` نمایش داده می‌شود:

```bash
st setup pg-node    # نصب نود پاسارگارد
st setup xui        # نصب پنل x-ui
st setup status     # مشاهدهٔ وضعیت نصب پنل‌ها و نودها
```

## ✨ اصول طراحی

| اصل | توضیح |
| --- | --- |
| **مصرف صفر ⚡** | ابزار پس از تنظیم کرنل خارج می‌شود؛ هیچ daemon، cron یا telemetry در پس‌زمینه باقی نمی‌ماند. |
| **ظرفیت‌محور 📊** | جدول `conntrack` و بافرها بر اساس تیر یا **تعداد واقعی کاربر** (`--users`) با پیش‌بینی دقیق RAM تنظیم می‌شوند. |
| **بی‌رگرسیون 🛡️** | کلیدهای حافظه به‌صورت سقفی تنظیم می‌شوند و هرگز پایین‌تر از مقدار پیش‌فرض کرنل مدرن نمی‌روند. |
| **رول‌بک واقعی ♻️** | پیش از هر تغییر، فایل در `manifest.tsv` ثبت و یک نسخهٔ دست‌نخورده در `original/` برای همیشه نگهداری می‌شود. |
| **گزارش صادقانه ✅** | هر مرحله وضعیت واقعی (`OK` / `WARN` / `SKIPPED` / `FAILED`) را گزارش می‌دهد و پس از اعمال، مقدار زندهٔ کرنل و DNS بررسی می‌شود. |
| **کیفیت تست‌شده 🧪** | بررسی مداوم با ShellCheck و shfmt در CI و تست بوت روی Ubuntu 20.04/22.04/24.04 و Debian 11/12. |

## ⌨️ مرجع کامل دستورات CLI

```text
st                              باز کردن منوی تعاملی و داشبورد وضعیت
st go                           تشخیص، بهینه‌سازی کامل و نمایش سلامت بدون هیچ سؤالی
st --status [--json]            گزارش کامل وضعیت سیستم، شبکه و کرنل (متنی یا JSON)
st --auto                       بهینه‌سازی غیرتعاملی (پایه + پروفایل تشخیص‌داده‌شده)
  --profile NAME                general | vpn-node | wireguard | bridge | panel | accounting | full
  --tier S|M|L|XL               انتخاب دستی تیر ظرفیت
  --users N                     سایزدهی conntrack بر اساس تعداد کاربر همزمان
  --qdisc fq|fq_codel|cake      انتخاب صف شبکه همراه BBR (پیش‌فرض: fq_codel)
  --anti-flood                  فعال‌سازی محافظت کرنلی در برابر SYN/Connection Flood
  --dns VALUE                   cloudflare | google | quad9 | opendns | shecan | electro | begzar | "ip1,ip2"
  --no-swap / --no-limits       حذف مراحل دلخواه در حالت --auto
  --no-extras / --no-perf / --no-priority
st --dry-run                    نمایش پلن و diff دقیق sysctl بدون اعمال هیچ تغییری
st --verify [--json]            Doctor: بررسی پایداری تنظیمات و تشخیص drift (خروجی متنی یا JSON)
st --report                     تولید و ذخیرهٔ گزارش متنی کامل برای پشتیبانی
st --rollback                   بازگردانی آخرین اجرای ثبت‌شده
st --rollback-original          بازگشت کامل به وضعیت پیش از اولین اجرای ابزار
st repair                       اطمینان از فعال‌ماندن تمام سرویس‌های oneshot پس از ریبوت
st boost                        اعمال مجدد اولویت CPU و محافظ OOM برای پروسه‌ها/کانتینرهای پروکسی
st isp SUB [ARGS]               مدیریت مسدودساز ISPهای ایران (status | live | check | scope | block | unblock | update)
st setup APP                    نصب رسمی پنل/نود (pg-node | xui | status)
st --install / st --update      نصب به‌عنوان دستور st / به‌روزرسانی خودکار
--no-color · --debug · -v · -h
```

**کدهای خروج (مناسب برای Ansible و اسکریپت‌های اتوماسیون):** `0` موفق · `1` شکست حداقل یک مرحله · `2` خطای دستور · `3` اعمال‌شده همراه با هشدار یا تشخیص drift.

## 🛠️ ساختار مخزن و توسعه

```text
src/       کد منبع ماژولار (core/ + modules/ + menu.sh + 99-main.sh)
data/isp/  دیتابیس رنج IP اپراتورهای ایران (به‌صورت داخلی در خروجی بیلد تعبیه می‌شود)
build.sh   کامپایل ماژول‌های src/ و data/isp/ به تک‌فایل dist/server-tools.sh
dist/      فایل نهایی تولیدی برای اجرا توسط کاربر (مستقیماً ویرایش نشود)
docs/      مستندات و مشخصات فنی
tests/     تست‌های smoke
legacy/    نسخهٔ ۱ (فریزشده)
```

```bash
./build.sh        # ساخت dist/server-tools.sh
make lint         # بررسی با ShellCheck و shfmt
./tests/smoke.sh  # اجرای تست‌های سریع بدون نیاز به root
```
